## Incident Summary

Between **06 October 2026 13:50** and **07 October 2026 12:16** (UTC+2), a threat actor:

1. Created **four rogue service accounts** in Active Directory (`svc_backup`, `administrator2`, `svc_test2`, `svc_test3`, `svc_monitor`)
2. Escalated `svc_test3` to **Domain Admin** membership
3. Cleared the Windows Security event log **three times** to destroy forensic evidence

The attack was surfaced by structured **threat hunting** on 08 October, which correlated scattered SIEM alerts into a unified attack timeline and justified P1 escalation.

**Attack TTPs:**

| MITRE ID | Technique | Evidence |
|---|---|---|
| T1136.001 | Create Account — Local Account | Event 4720 × 5 |
| T1098.007 | Account Manipulation — DA escalation | Event 4728 × 1 (rule 100004) |
| T1070.001 | Clear Windows Event Logs | Event 1102 × 3 (rule 100005) |

### Phase 3 — Containment

**Actions taken (PowerShell on WIN-SERVER):**

```powershell
# Disable all rogue accounts
Disable-ADAccount -Identity "svc_backup"
Disable-ADAccount -Identity "administrator2"
Disable-ADAccount -Identity "svc_test3"
Disable-ADAccount -Identity "svc_monitor"

# Verify — all should return Enabled: False
Get-ADUser -Filter {
  SamAccountName -like "svc_backup" -or
  SamAccountName -like "administrator2" -or
  SamAccountName -like "svc_test3" -or
  SamAccountName -like "svc_monitor"
} | Select Name, SamAccountName, Enabled

# Remove svc_test3 from Domain Admins
Remove-ADGroupMember -Identity "Domain Admins" -Members "svc_test3" -Confirm:$false

# Audit tier-0 groups
Get-ADGroupMember -Identity "Domain Admins" | Select Name, SamAccountName
Get-ADGroupMember -Identity "Enterprise Admins" | Select Name, SamAccountName
Get-ADGroupMember -Identity "Schema Admins" | Select Name, SamAccountName
Get-ADGroupMember -Identity "Administrators" | Select Name, SamAccountName
```

**Results:**
- All 4 accounts: `Enabled: False` ✅
- Domain Admins: Administrator only ✅
- Enterprise Admins: Administrator only ✅
- Schema Admins: Administrator only ✅
- Administrators: jay.reed, Domain Admins, Enterprise Admins, Administrator (expected) ✅

### Phase 5 — Eradication

```powershell
# Permanently remove all rogue accounts
Remove-ADUser -Identity "svc_backup" -Confirm:$false
Remove-ADUser -Identity "administrator2" -Confirm:$false
Remove-ADUser -Identity "svc_test3" -Confirm:$false
Remove-ADUser -Identity "svc_monitor" -Confirm:$false

# Verify — should return empty
Get-ADUser -Filter {
  SamAccountName -like "svc_backup" -or
  SamAccountName -like "administrator2" -or
  SamAccountName -like "svc_test3" -or
  SamAccountName -like "svc_monitor"
} | Select Name, SamAccountName

# Reset Administrator password (credential rotation)
Set-ADAccountPassword -Identity "Administrator" -NewPassword (Read-Host -AsSecureString) -Reset
```

**Result:** Verification query returned **empty** — all accounts purged ✅

## Detection Engineering Insight

This project validated three custom rules written in Project 3:

| Rule | Level | What it caught |
|---|---|---|
| 100003 | 12 | All 5 account creation events (Event 4720) |
| 100004 | 14 | DA escalation of svc_test3 (Event 4728) |
| 100005 | 15 | Final log clearing event (Event 1102) |

**The gap:** The first two log clearing events fired only at Level 5 (default rule 63103) — insufficient for SOC paging. The proposed remediation is a correlation rule (100006) that would auto-escalate any log clearing event occurring within 60 minutes of a rogue account creation.
